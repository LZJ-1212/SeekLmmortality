# 宣称奇迹与不合理行动（分层，不是一个「AI 判不合理」）

规格先行。**自由度总则**（玩家能说什么、天道锁什么、何时配新代码）见 [player_agency.md](./player_agency.md)。情境硬锁见 [situation.md](./situation.md)。战斗铁律见 `combat.service.ts`（差两大境秒杀，功法/仙缘/**捡神器都不能取消**）。本文件回答两件事：

1. 「战中捡绝世武器反杀」这种**有可能、但看气运**的句子，**什么时候**才跑掷骰代码。  
2. 其它乱七八糟的输入，**不靠一个万能分类器**，靠分层。

**L1 代码：** 情境锁已做；本文件的仙缘奇迹骰 **尚未接线**（路线图 **A5 / S36**）。自由度总则已写，禁止先让模型演神兵。

---

## 1. 不要做什么

| 做法 | 为什么不行 |
|------|------------|
| 让 DeepSeek 判断「这句话合不合理」 | 模型会顺着玩家演；还会编神器。贵。 |
| 一个「不合理」黑名单想穷尽所有句子 | 换个说法就绕过。 |
| 仙缘骰成功 → 秒杀高两境的敌人 | 违反境界压制铁律。气运不是龙傲天开关。 |
| 成功就往背包塞任意「绝世神兵」 | 物品必须在图鉴或本局自定义条目里，见 AI 物品铁律。 |

已经有、能挡一部分的：

- 注入句（改数值/套密钥）→ 黑名单，不调模型。  
- 战中闭关/坊市/炼丹/双修 → 情境锁 400。  
- 声称使用图鉴里有、背包里没有的道具 → `detectFabricatedItemUsage`。  
- AI 报的战斗伤害/胜负 → `resolveCombatModifiers` 重算；差 ≥2 大境仍秒杀。

挡不住的：玩家打「我捡到绝世武器反杀了他」——句子里没有图鉴物名，闭关拦截器也不触发，模型很容易写成你赢了。这要靠下面第 3 层「宣称奇迹」。

## 2. 三层（由硬到软）

```
玩家输入
  │
  ├─ 层 1 硬拒绝     与当前情境物理上不能同时成立（战中闭关）
  │                  → 400，不调 AI，不掷骰
  │
  ├─ 层 2 铁律覆盖   境界差、死亡锁、日限、物品熔断
  │                  → 可调 AI，但 forcedOutcome 锁死；骰子改不了秒杀
  │
  └─ 层 3 宣称奇迹   玩家用语言「宣布」一件本不该由他决定的好运
                     → 仅当命中封闭意图表 才掷仙缘骰
                     → 成功/失败都写进 forcedOutcome，AI 只准描写
```

层 3 **默认不跑**。大多数话（砍一刀、求饶、逃跑、喝酒壮胆）走 `other`，不掷骰，交给战斗公式 + 模型叙事。

## 3. 「仙缘奇迹骰」何时触发（拍死）

必须**同时**满足：

1. `detectMiracleClaim(action)` 命中下表**封闭意图**（子串，和闭关检测一样，可单测，禁止上模型分类）。**不要求**上一回合已是 `combat`（第一刀就喊反杀也要检）。  
2. 本句不是层 1 已拒绝的意图（战中闭关等仍走情境锁 400，不进本骰）。

境界差只影响**骰成功上限**（见 3.2），不作为「要不要跑这段代码」的条件。未命中表 → **不调用**本骰子函数。

### 3.1 封闭意图表（L1 只做这几条）

| 意图 id | 触发子串（例，实现时写死数组） | 骰成功最多给什么 | 骰失败 |
|---------|-------------------------------|------------------|--------|
| `miracle_reversal` | 反杀、绝地逢生、以弱胜强、逆转战局 | 见 3.2 | 妄念落空，对方出手更狠（可略增本回合承伤，由战斗公式吃） |
| `miracle_loot` | 绝世武器、神兵、神器、天降法宝、捡到.*（剑\|刀\|枪） | 图鉴内**下品/凡器**一条，或本战临时 +伤害乘数（不入库） | 摸到的是断刃/石头，无物 |
| `miracle_instant_kill` | 秒杀对方、一招毙命、直接打死他 | **禁止**当秒杀用。若境界不劣于对方，按 `miracle_reversal` 成功档；若差 ≥1 大境，当作失败档 | 同失败 |

一句命中多条：优先级 `miracle_instant_kill` > `miracle_loot` > `miracle_reversal`（先处理最狂的宣称）。

未命中表 → **不调用**本骰子函数。这就是「什么情况会触发这段代码」的唯一答案：`detectMiracleClaim` 非空。

### 3.2 成功了也不能破铁律

先算 `realmGap`（玩家境 − 敌境，敌境仍来自本回合 AI 报的 `combat.enemy_realm_major`，或交手锁里缓存的敌境——缓存更好，避免模型把金丹报成炼气）。

| 境界差 | 仙缘骰成功的上限 |
|--------|------------------|
| 敌高 ≥2 境 | **骰子作废**，仍 `enemy_instant_win`。forcedOutcome 写明：气运再好也难逃降维。 |
| 敌高 1 境 | 最多：本回合承伤再乘 0.7，或允许「脱身」结束交手（情境改 `none`），**不许**把对方打死。 |
| 同境或玩家更高 | 可给：图鉴凡器一件，或本回合对敌伤害 ×1.2；仍走 `normal` 伤害，不改成 `player_instant_win`（除非公式本身已是玩家碾压）。 |

仙缘只改**概率和上限档**，不改秒杀阈值。

### 3.3 概率公式（拟，与奇遇骰同风格）

与历练奇遇一样：可注入 `rollFn`，单测用 `() => 0` / `() => 0.99`。

```
chancePercent = clamp(3 + (fortune - 10) * 1.2, 1, 25)
triggered = (1d100 <= chancePercent)
```

仙缘 10 → 约 3%；仙缘 15 → 约 9%；上限 25%，避免气运满点场场神兵。  
未触发 = 失败档，不是「当没说过」。

## 4. 层 2 仍要防模型圆谎（骰完之后）

即使没走层 3：

- `item_changes` 里出现图鉴没有、背包没有的名字 → 丢掉，forcedOutcome 补「并无此物」。  
- `combat.outcome` 或伤害数字不采信，只采信 `resolveCombatModifiers`。  
- 玩家说「我已经金丹了」不改 `realm_major`。

这是第二道网：漏检的狂句最多变成「你这么想，天地不认」。

## 5. 其它「不合理」怎么归类（免得无限加 if）

| 类型 | 例子 | 归哪一层 |
|------|------|----------|
| 时空/身份不能同时 | 战中闭关、死人还行动 | 层 1 情境/死亡锁 |
| 宣称改存档数字 | 把修为改为 999 | 注入黑名单 |
| 宣称用没有的字典物 | 捏碎某张已登记符 | 物品熔断 |
| 宣称奇迹好运 | 捡神器反杀 | 层 3 封闭表 + 仙缘骰 |
| 普通胡话、玩笑、诗 | 我变成一只鸡 | **不拦截**；模型当戏言，数值不动 |
| 真要穷举社交/地理 | 「瞬移去中州」 | 以后 S31 赶路；未做前最多叙事、不改 `current_location` 到未邻接地点（地点表未接邻接前：可暂不改地点） |

原则：**只有「会改数值或发物品」的宣称才配代码。** 纯文戏让模型演，拦截器不给修为、不给神兵。

## 6. 实现落点（未开工，排期 A5）

```
backend/src/services/miracle.service.ts
  detectMiracleClaim(action): MiracleClaim | null
  rollMiracle(fortune, claim, realmGap, rollFn): MiracleRoll
```

`/api/action`：情境锁通过后、闭关等拦截器之前或之后均可，但必须在 `deduceAction` **之前**算出 `forcedOutcome` 片段。差两大境时不要等 AI 报敌境——若无缓存敌境，本回合先让 AI 报 `combat`，**落地伤害仍按公式**；仙缘物品等到敌境已知再发（可本回合只改 forcedOutcome 叙事，物品下回合发——L1 允许「本回合只锁叙事，不发神兵」以减复杂度）。

**L1 推荐更薄：** 层 3 成功也不发物品，只写 forcedOutcome「气运微澜，多出一线生机（承伤略减）」；物品留给有图鉴掉落表之后。先把「狂句必骰、骰不破秒杀」做硬。

## 7. 验收（层 3 落地时）

- `combat` + 「闭关」仍走情境锁，不进奇迹骰。  
- 「我发现绝世武器反杀」→ `detectMiracleClaim` 非空 → 必有一次注入骰子的单测。  
- `rollFn` 使失败：无新物品，forcedOutcome 含落空。  
- 敌高两境：无论骰子，结局仍秒杀。  
- 未点名神器/反杀的「再刺一剑」→ `detectMiracleClaim` 为 null，不掷本骰。
