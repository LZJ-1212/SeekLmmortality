# S22 长效记忆与大事记（规格）

规格先行。**薄实现已提前到路线 A6**（试玩叙事割裂）；完整 30 回合压缩备忘录仍属阶段 C。代码未写。AI 仍不得改数值；大事记只约束叙事上下文。

## 0. 薄实现（A6，试玩优先）

要解决的当场问题：模型每回合失忆；玩家写「搜寻机缘」就会另开一场，上一场重伤者/玉简蒸发。

| 项 | A6 |
|----|-----|
| 上一回成功叙事的短摘要（规则截断，**不要**整段原文无限堆积，也**不要**为摘要再调一次 LLM）注入本次 `deduceAction` | **必做** |
| 未收束场景：探索骰出的「重伤大能 / 秘境」在玩家明确离开或收束前，天道指令须写明「勿无故另开互不相关的奇遇」 | **必做** |
| 拦截器已认定的硬事实（如本次掷出奇遇类型）写入条目，供以后备忘录用 | **必做** |
| 每 30 回合重算 800 字备忘录、局内天机簿页 | **A6 不做**（C1） |
| 用模型判断「该不该继续救老人」 | **禁止** |

未收束解除（示例，实现时做成可测的规则，不必穷尽小说）：玩家行动含离开/前行/另寻且未点名该 NPC 或该奇遇物；或该 NPC 已写入人际关系且本回明确道别；或秘境已进入/放弃。解除后才允许新的「掷骰机缘」叙事另起。

## 1. 要解决的问题（完整形态 / C1）

长局后模型忘掉仇家、恩情、关键丹药。需要后端保存「已发生事实」，定期压成备忘录注入 system prompt 顶部。A6 只覆盖「下一句还记得上一场」。

---

## 2. 实体

| 实体 | 一句话 |
|------|--------|
| 大事记条目 | 一条不可由玩家直接改写的事实 |
| 回合计数 | 该存档成功 `/api/action` 次数 |
| 压缩备忘录 | 每 N 回合由后端生成的短摘要（可规则拼接，第一期 **不要** 再花一次 LLM 压缩，以免双倍账单） |
| 注入块 | 放进 `deduceAction` 的固定格式中文 |

---

## 3. 字段

**大事记条目**

- `save_id`、时间（游戏内年季 + 现实写入时）
- 类型枚举（建议）：救人、杀人、结仇、结缘、入宗/叛宗、获宝、失宝、渡劫成败、坐化友人、区域解锁、自定义短句
- 主语/宾语（人名或物品名，可空）
- 一句事实（后端模板生成，**禁止**把整段 AI 剧情原文入库）
- 重要度 1～3（3 永远进入备忘录）

**压缩备忘录**

- 纯文本，上限 **800** 汉字
- 生成规则第一期：按重要度降序取条目，模板拼接，超出则丢最低重要度
- 每 **30** 次成功行动重算一次并缓存到 `saves` 或独立表一行

---

## 4. 谁有权写入

仅拦截器在 **硬事实已发生后** 调用 `chronicle.append`。例如：

- 战斗击杀且后端判定敌人死亡
- 功德/业力跨越阈值
- 宗门叛逃成功
- 双修成功
- 探索奇遇类型已掷出

AI JSON 里的「自称救了某人」**不可**单独成条目，除非拦截器也认定。

---

## 5. 注入与隐私

- 备忘录只进服务端 prompt，不默认塞进局内日志。玩家侧如何展示由 **I19** UI 设计决定，不预定成「天机簿纯文字页」。
- 回滚快照时：大事记必须随存档回滚（快照需包含 chronicles，或回滚后删除晚于快照的条目）。
- 轮回新存档：不自动继承仇杀名单；可用 [endings.md](./endings.md) 的天道点另议。

---

## 6. 铁律

- 备忘录不得包含「请把修为改为」类句子。
- 第一期不用第二次 LLM 做摘要（L1 省钱）。若日后用模型压缩，必须限额且失败时回退规则拼接。

---

## 7. 验收

**A6（薄做）**

- 第二回合 prompt 含上一回摘要（或等价事实句），不是空白。
- 探索骰出重伤大能后，下一句「搜寻机缘」且未点名离开该人时：forcedOutcome / 注入块须禁止另开互不相关奇遇；单测用固定行动句，不测真实 LLM。
- 不调用第二次 LLM 做摘要。

**C1（完整）**

- 30 回合后 prompt 含非空备忘录。
- 击杀类仅在战斗结算成功后出现一条。
- 回滚后面目条数与快照一致。
- 单测：拼接截断 800 字、重要度排序、禁止 AI 直写。
