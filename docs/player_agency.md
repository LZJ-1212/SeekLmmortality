## 1. 产品立场

这是文字修仙，不是选择题 RPG。玩家用自然语言试探世界，这是核心乐趣。

乐趣停在「宣布结果」之前：

- **允许：** 我想怎么打、怎么骗、怎么逃、怎么吹牛、写诗、说胡话。  
- **不允许：** 这句话本身变成「我赢了 / 我金丹了 / 我有绝世神兵了」。

DeepSeek 只描写。禁止用模型给每句打「合不合理」分（贵、会顺着演、换个说法就绕过）。

## 2. 三圈边界

```
┌─────────────────────────────────────────┐
│  外圈 · 文戏自由                         │
│  任意口吻、玩笑、诗、试探、谎言、求饶     │
│  拦截器不拦；数值不动；AI 当戏言或氛围    │
├─────────────────────────────────────────┤
│  中圈 · 检定自由                         │
│  行动成立，结果由公式/掷骰决定            │
│  例：历练奇遇、突破雷劫、宣称反杀（A5）   │
├─────────────────────────────────────────┤
│  内圈 · 天道禁区                         │
│  物理上不能同时、改存档、破境界压制       │
│  400 或不调模型，或 forcedOutcome 锁死    │
└─────────────────────────────────────────┘
```

判断一句输入落在哪一圈，只问三件事（按顺序）：

1. **会不会直接改存档数字或发不存在的物品？** → 内圈或中圈，必须有代码。  
2. **与当前情境能否同时发生？**（战中闭关）→ 内圈，硬拒绝。  
3. **只是文戏、不改数？** → 外圈，放过。

未点名的狂句漏进模型：层 2 仍丢掉非法物品、重算战斗。最多变成「你这么想，天地不认」。

## 3. 玩家拥有 vs 天道拥有

| 玩家可以说 / 可以试 | 天道（后端）说了算 |
|---------------------|-------------------|
| 攻击、防御、逃、骗、求饶、谈判的**意图** | 伤害、胜负、是否秒杀 |
| 「我想捡到一把剑」 | 背包是否真多一件；必须是图鉴或本局自定义条目 |
| 「气运爆发反杀」 | 是否掷骰、骰成功上限；**永不**取消差两大境秒杀 |
| 闭关几年 | 月数换算、修为公式、寿元；交手当口直接拒绝 |
| 「我已金丹 / 修为九千」 | `realm_major`、修为字段不听这句话 |
| 对 NPC 的态度、誓言（未来 S27） | 未实现前不改功德/名声账；实现后仍走服务不是模型 |

仙缘（六维里的运气）只提高**中圈检定**的概率，不是内圈通行证。

## 4. 内圈清单（已实现 + 拍死的）

下列宣称无论文笔多好，都不得由 AI 圆成成功：

| 边界 | 处理 | 状态 |
|------|------|------|
| 死亡后再行动 | 死亡锁，拒绝 action | 已做 |
| 战中闭关 / 坊市 / 拍卖 / 炼丹器 / 双修 | 情境锁 400，不占日限 | 已做 |
| 提示词注入、命令改规则、改数值套话 | 网关黑名单 | 已做 |
| 使用图鉴有、背包无的道具 | 熔断，效果落空 | 已做 |
| 未习功法却催动法术/神通 | `forcedOutcome` 落空，只准拳脚兵刃 | **薄做**（`technique.service.ts`）；招式库仍待 S20 |
| 拜访/请教已仙逝 NPC | `forcedOutcome` 人去楼空，亡者不得出场 | **已做**（`deceasedNpcForcedOutcome`） |
| 敌高 ≥2 大境仍要赢 | 战斗公式秒杀；功法/仙缘/神器宣称都不能取消 | 已做（公式）；宣称神器见 A5 |
| 瞬移改地点到未邻接处 | S31 前：可不改 `current_location` | 未做地理；先不扩表 |

**不要**为「我变成一只鸡」加拒绝码：外圈。

## 5. 中圈：何时才配一颗骰子

只在玩家**宣布一件本不该由他决定的好运或结果**时，才写封闭意图表 + 可注入 `rollFn` 的纯函数。

触发原则（细节与词表见 [plausibility.md](./plausibility.md)）：

- **默认不掷。**「再刺一剑」不跑奇迹代码。  
- **命中封闭子串才掷。** 禁止 NLP / 二次 LLM 分类。  
- **失败也要写进 `forcedOutcome`。** 不是当没说过。  
- **成功有上限。** 不发无名神器；不改秒杀阈值。L1 薄做甚至可以成功也不发物品，只锁叙事或略减承伤。

已有同类中圈（不要重复造轮）：历练 `rollExplorationEncounter`、突破雷劫骰、天罚骰。新骰子必须能单测，禁止 `Math.random()` 写死在路由里。

## 6. 什么时候才加新规则（防无限 if）

| 现象 | 该不该开工 |
|------|------------|
| 朋友试玩反复用同一句改胜负/发神兵 | 应进封闭表（A5） |
| 偶发一句诗、玩笑 | 不开工 |
| 与情境互斥且会走错误拦截器（战中闭关加修为） | 层 1 硬锁 |
| 想用模型「灵活判断」 | **禁止**当方案 |
| 地理瞬移、城里杀人 | 等 S31 / S32，不要用业力冒充 |

加词条必须能写出测试用例名：「玩家输入什么会走到这条」。

## 7. `/api/action` 心智顺序（实现时）

与 [architecture.md](./architecture.md) 对齐。插入新锁不得调换「先算再调模型」：

1. 网关：口令、净化、黑名单、死亡锁  
2. 层 1 情境锁（可能 400，不占日限）  
3. 日限  
4. 既有拦截器（闭关、突破、物品熔断等）  
5. **A5：** `detectMiracleClaim` → 若非空则 `rollMiracle`，拼 `forcedOutcome`  
6. 调 AI  
7. 战斗公式覆盖胜负；过滤非法 `item_changes`；写回情境  

A5 未接线前，第 5 步跳过；第 7 步仍有效。

## 8. 对玩家可见的体验（文案原则）

短讯用修仙口吻，不报堆栈。

- 内圈拒绝：像「刀未入鞘，岂能闭关」——**明确办不到**。  
- 中圈失败：像「妄念落空，断刃在手」——**试过了，天不认**。  
- 外圈：不必系统弹窗训人。
